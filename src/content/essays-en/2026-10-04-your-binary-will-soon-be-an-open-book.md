When software is compiled, the source code becomes machine code, which has traditionally been practically impossible to reverse. Decompilation is the way back to readable code that can be used to understand how the program works and build on it.

Specialists have been able to do this for a long time, but it is slow and difficult. Modern AI changes the picture. Agents can search through large amounts of code, connect findings and test whether their explanations hold. That dramatically lowers the threshold for examining software that used to be too time-consuming to take apart.

For a practical example, look at Halo: Combat Evolved. The game has been decompiled with AI help, and the code from the old Xbox release has been ported to Windows, Linux and Android. You can even play it in a browser.

Not long ago this was unthinkable. If development continues (it will), it will become far cheaper to read, modify and hunt for weaknesses in software you distribute. "Closed source" will offer less and less protection against people who actually want to understand what the program does; it might as well be open source.

Passwords, keys and security logic sitting in the client program are within reach for anyone who has the binary. AI will make the search dramatically faster. At the same time, the models are getting better at concrete tasks such as finding and exploiting vulnerabilities.

What can your software withstand when an attacker can use an agent to read it?

If the answer is "we assume nobody can be bothered", you need a new plan.
